# 召回最终审查：统一路标、最佳实践与未完成的工程

审查日期：2026-11-06。结论：**模型参考与研究资料已较完整，生产召回闭环仍未完成。**重点应从继续增加模型名转向可用数据、采样训练、资格与版本、真实检索、融合、新鲜度和线上证据。不存在不依赖业务、规模和资源的单一“业界最佳模型”。

当前唯一总入口为 [召回总路标](README.md)，模型/组件/系统能力统一登记在 [roadmap.json](../../configs/recall/roadmap.json)。SDM 的 S1/S2、位置偏差的 B1/B2 与 ANN、融合、探索、实验使用同一编号与交付台账，不再只作为附录链接。

## 2. 业界实践的合理目标形态

更稳妥的目标是：**稳定低成本通道 + 特征化向量主干 + 实时意图/多兴趣/内容语义补充 + 可控探索 + 多路融合 + 一致索引与实验闭环**。

不是每个业务都要同时用 SDM、MIND、DR、SA、图、HSTU。一个通道是否保留，取决于同预算下的独有优质候选、最终消费贡献、稳定性和维护成本。成熟 ItemCF/关注/热点可以长期保留；生成式召回先旁路检验，不直接替换稳定供给。

这是基于可定位公开实现与工程约束的审查建议，不声称复原任何公司当前生产系统，更不声称穷尽截至审查日的所有最新论文。

## 3. P0：先补数据、样本与目标合同

必须明确请求、可推荐目录、可视曝光/有效起播、事件发生/接收/特征生效时间、标签成熟窗口、动作与归因。内容发布时间、下架、删除和用户屏蔽必须影响当时的候选集合。

现有合成实验假设全部内容起始时可推荐、用户/内容 ID 已在词表，且同一步事件对齐。它不能证明真实日志回放正确。真实数据不满足全局时间条件时，当前程序会拒绝；不应删除检查来“跑出指标”。

训练目标应按场景分别定义：列表点击与点击后消费不同；视频起播不是强正例；快划需排除故障；复播与首轮观看不同。历史强度、训练样本权重、采样概率和 propensity 分别定义，不能混成一个无类型 weight。

## 4. P0：训练采样与负例是主干能力，不是后续调参

当前六模型采用全目录 CE，目录上限 20,000，没有工业 sampled-softmax、batch negatives 或分布式参数服务。目录扩大前应先建设 T0，而不是仅换用户编码器。

官方 TFRS Retrieval 实现提供候选采样概率修正、accidental-hit 去除、困难负例筛选等明确接口。本轮固定版本中先处理温度、采样概率，再去除重复正例/筛选负例；需按实际目标审查调用顺序和假设，不能只减一个全局频率。

必须同时检查：

- batch 内相同 item 的假负例；同用户其他真实兴趣不等于强负例；
- 随机、曝光未消费、困难负例的混合与来源；
- 困难负例挖掘的模型/索引版本和时间；
- queue/跨 batch 表征的陈旧性；
- 新内容、长尾、重度用户的采样倾斜；
- 点击偏差与 `q(sample)`、`e(examination)`、`π(action)` 的区别。

相关官方代码与哈希见 [final-review-sources.json](evidence/final-review-sources.json)。TFRS 的 sampled-retrieval 接口不能被当作本仓库已完成同等实现的证据。

## 5. P0：ANN、资格与新鲜度必须共同评估

当前 `index.pt` 是精确向量表，**没有 ANN**。下一工作包应先建立同目录、同距离、同归一化的精确基准，再选择 Flat、HNSW、IVF/PQ 等候选并实测。没有一种索引在所有更新率、内存和尾延迟约束下都最优。

Faiss 官方 README 明确区分搜索时间、质量、内存、训练/添加成本等权衡，余弦检索依赖归一化；`Index` 接口还有 metric、is_trained、add/search/remove 等不同能力。接口存在不代表所有索引都支持相同增删语义，应逐类型测试。

两类 Recall 要分别报告：

\[
Recall_{ANN}@K=|ANN_K\cap Exact_K|/K,
\quad Recall_{business}=|Candidates\cap G|/|G|.
\]

前者测近似损失，后者还受模型、资格与日志正例选择影响。`G` 必须明确是真实可推荐、可观察的评价正例集合，不能把旧曝光日志当成完整兴趣真值。

先过滤与后过滤各有代价：索引资格分区/bitmap 可减少无效结果，但策略和更新更复杂；后过滤简单却可能导致缺量。应提供有界 overfetch、回填和短结果诊断，不能为补满而放回屏蔽/下架内容。

模型、内容编码器、向量空间和主/增量索引要版本兼容。需要测新增到可检索延迟、删除到不可见延迟、双版本切换内存、回滚和冷启动缓存；checkpoint 文件 hash 只是其中一个组件。

## 6. P0：多路融合是独立决策层

原来直接把多个 Top-K 合并的设计缺少分数语义、配额、来源与退化处理。本次新增 [fusion.py](../../recommender/retrieval/fusion.py) 作为可运行基线：

\[
s(i)=\sum_{c:i\in c}\frac{w_c}{k+rank_c(i)}.
\]

采用 rank-based RRF，避免直接比较不同塔/图/规则通道的原始分数。它是可检查的起点，不是学习式校准或证明最佳的线上策略。

组件明确执行：资格/已看过滤 → 通道内去重 → 保留全部来源、rank 和原始诊断分 → best-effort 最小配额 → 全局去重与补量；通道不可用、不足候选、配额缺口均报告。

### 6.1 配额语义不能含混

每个输出 item 只有一个 `selected_by` owner，但保留所有命中来源。`max_quota` 限制 owner 数，**不限制某来源出现在 provenance 中的总数**。如果业务要求任一来源覆盖占比上限或主题/作者强约束，应使用另外的约束选择器，不能声称当前 owner 配额已解决。

最小配额是 best-effort：来源重叠、资格过滤与退化可能使它无法满足。组件会显式报告，而不会重复内容、越过强准入或秘密放宽上限。资格查询错误直接失败，不 fail-open。

### 6.2 通道贡献评估

同时记录命中、独有候选、多路重叠、融合保留、粗精排选择、最终曝光和消费。关闭通道实验应保持总候选/服务预算合理可比，避免把留空预算损失当作该通道的全部价值。

原始分数可作为后级特征，但在校准前不直接跨模型相加。动态配额、探索保证、内容生态与用户状态是后续策略层，不由 RRF 一项包办。

运行实际导出查询 smoke：

```bash
/workspace/recsys-venv/bin/python -m tools.fuse_recall_demo \
  --checkpoint-root artifacts/recall-demo/seed17
```

它读取已有合成模型的 checkpoint/index，融合 pooled、session_gate、mind_ref 各 20 候选到预算 10。[保存结果](evidence/fusion-smoke.json) 不作为真实用户或融合收益实验；组件尚未接入生产请求编排。

## 7. P0/P1：SDM 与消偏应接入主线，但有不同前置条件

S1/S2 已在统一台账标记 C，代表会话/时间/action 与门控组件经过测试；不是新模型已经训练。B1 也是 C，B2 的真实位置识别与校准仍是 P。

建议分两条并行准备：

- 序列线：补齐真实 session、动作与 as-of → 对照衰减池化/当前固定窗口 → 接新组件训练 → 切换与空会话切片 → 缓存/新鲜度。
- 消偏线：确定观察机制与随机/可识别数据 → propensity sidecar → 支持集/尺度/ESS → 接正例目标 → 独立干预集评价。

最后做“原/新编码器 × 原/校正目标”的 2×2 对照，区分来源；没有校准数据时不从历史位置生成 propensity。视频流深度也不能直接当作列表 examination 衰减。

## 8. P1：新用户、新内容与探索不能只靠更多 Embedding

现有 query 对未知 user ID 报错；类别字段选项不等于多模态；目前没有新内容分层探索。需要定义：

1. 新用户：入口/上下文、关系/地域/质量供给及明确 OOV 路径；
2. 新内容：内容与作者先验、准入、增量入库和受控机会；
3. 反馈积累：小样本置信度、扩大分发与衰减，不凭一次高反馈放大；
4. 探索日志：资格池、抽样概率、观察窗口及负反馈保护；
5. 长期生态：优质新作者/内容发现、主题/作者集中、重复与满意度。

KuaiRand 的随机曝光仅覆盖限定内容池和干预人群，不能作为全库任意策略无偏的证明。其既有核验资料支持建立随机保留集的研究路径，不支持任意迁移收益数字。

## 9. P0：诊断损失发生在哪一层

逐请求追踪正例/高价值候选是否经过：可推荐目录 → 召回 → 资格过滤 → 融合 → 粗排 → 最终曝光。对于完整嵌套事件，条件保留率的乘积是链式分解，不要求各层独立；实际回填和重复来源也需纳入同一 trace。

不能只看原始召回 Recall：它可能被下架/重复内容撑高，也可能在融合被丢掉。应分场景、新老用户、内容年龄、片长、活跃层级、兴趣切换、流量峰值和退化请求检查。

单目标新颖 item 的小合成测试不能替代视频复播、多正例有效观看或随机干预集。现有测试中的重复目标会被计数并跳过，真实业务必须单独定义重复消费评价，不能忽略这部分后声称全消费覆盖。

## 10. P0：在线约束是质量的一部分

请求级 deadline、并行通道隔离、有界重试、缓存失效、资格服务故障、稳定回退、尾延迟与资源峰值需要真实压测。更多候选、更多头或更长历史带来的计算增长可能抵消离线收益。

列出线上服务、离线编码、索引/状态存储、教师打分、冗余和维护的增量成本；同质量降本与同预算提质分别比较。没有业务 DAU、QPS、供给与单位价值，不能承诺统一 ROI 或固定采购量。

## 11. 收益估计的一个必要修正

在固定最终候选预算下，不能只加新通道找回的正例，还要扣掉被挤出的旧正例：

\[
\Delta Recall=(a-b)/|G|,
\qquad C_1=C_0+(1-C_0)q-d.
\]

`a` 是新增有效正例数，`b` 是丢失旧有效正例数，`d=b/|G|`。旧版只有前两项的公式仅对应 `d=0` 的理想情景。公开离线指标、toy 结果和验收目标也仍不能当作本业务预期。

真正的估计需加入资格、融合、后级选择、曝光与消费，并用受控实验更新区间。多模块收益不能机械相加；统计显著但小于成本门槛的改善也不应自动放量。

## 12. 最终建议的推进顺序

| 优先级 | 工作 | 交付证据 | 何时进入下一步 |
|---|---|---|---|
| P0-1 | D0/E0：真实数据和全链路 trace | 口径、时点、成熟标签与损失定位报告 | 可复现真实基线 |
| P0-2 | T0/V0/I0：采样、资格/版本、ANN | 近似损失、更新/删除/回滚、成本曲线 | 服务与新鲜度可承载 |
| P0-3 | F0/K0：融合和请求编排 | 组件到集成、退化/不足量/配额诊断 | 随机实验与回退可执行 |
| P1 | S1/S2/B1/B2、R6/C0：序列、消偏、冷启动 | 有识别条件的控制变量实验 | 真实价值和经济门槛通过 |
| P2 | 图增强、大序列、生成式 | 匹配预算的增量与复现 | 超过当前系统 Pareto 前沿 |

P0 与 P1 有可并行的数据准备，不是等待所有平台完工再做研究。已完成的本地组件可以进入下一轮集成；尚缺的数据与服务应继续保留 P，不能因为补了一篇文档就升级状态。

**当前可以说**：六模型参考训练与小目录查询、序列/消偏/融合组件、证据审计和统一路标已交付。**当前不能说**：工业 ANN、在线特征与编排、真实新内容探索、位置消偏训练收益、生产可用性或线上商业收益已经验证。
