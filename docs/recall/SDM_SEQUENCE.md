# SDM 与序列召回优化：从固定窗口到会话、时间、多行为与长期记忆

本专题补足原路标中 R3 的细节。当前已训练的 `session_gate` 只是一种 SDM 风格参考模型：固定最近 8 条、单层 LSTM、注意力和门控。它没有真实会话、时间间隔、多行为、长周期记忆或实时状态服务，不能把模型名字当作这些能力均已具备。

本专题已纳入 [统一交付台账](README.md#2-统一交付与依赖台账)：S1/S2 标记 **C（组件已测）**，SF0 仍为生产状态服务规划；真实训练、数据与验收依赖不因组件单测而自动通过。

[优化路线图](diagrams/05-sdm-sequence.svg) · [位置消偏专题](POSITION_DEBIAS.md) · [当前基线代码](../../recommender/retrieval/models.py#L112) · [新增序列组件](../../recommender/retrieval/sequence.py)。新增组件已通过前向/梯度测试，**未接入六模型训练器、未产生改进效果实验**。

## 1. 先拆清楚 SDM 的优化对象

设静态用户表征为 `eu`，请求前历史为 `H={(it,at,tt,ct)}`：内容、行为类型、事件时间、当时上下文。SDM 类 matching 模型的核心是：

1. 用短期分支识别当前需求；
2. 用长期分支保留稳定偏好；
3. 按用户与当前状态融合；
4. 输出可与全库内容向量检索的用户表示。

因此优化至少包括样本、会话、token、短期编码、长期记忆、融合、目标和服务八个部分，不能只做“LSTM 换 Transformer”。原 SDM 作者材料与公开版本限制见 [模型审计](../recommendation/22-model-by-model-evidence-audit.md)；下文是本项目优化设计，不冒充原论文配置。

## 2. S1：会话划分与序列数据质量

### 2.1 三类边界必须分别比较

| 方案 | 优点 | 主要失效模式 | 适用实验 |
|---|---|---|---|
| 固定最近 N 条 | 简单、长度可控 | 活跃度不同导致时间跨度差异大 | 当前基线 |
| 时间 gap 会话 | 区分长时间离开后的需求 | 同一意图被切断；连续浏览也可能已换兴趣 | 参数来自 gap 分布，按场景调优 |
| 产品 session/主题变化 | 可利用真实进入退出或主题转移 | 产品 session 不等于兴趣；变点算法会误判 | 比较产品边界、语义变化与混合边界 |

例如 gap 候选 5/30/120 分钟仅是实验网格，不是通用行业标准。应先测事件间隔分位数、会话长度、空分支率、跨会话兴趣一致性，以及最后一段的有效消费。

列表页要区分可视曝光与点击序列，避免将未看见卡片塞进兴趣负例；视频流要区分预取、真正播放、主动滑走、播放失败与退出。将播放器故障当作短期厌恶，会快速污染会话向量。

### 2.2 已补充的可运行代码

`build_sequence_features` 在截断前计算 session IDs，输出 ages/actions/session IDs，并拒绝请求时刻及之后的事件、不对齐字段、逆序时间。这个顺序很重要：先截断再重新划会话，可能丢失真实会话的延续信息。

输入历史仍需保证在当时已经到达在线系统。只检查 `event_time<request_time` 不能解决迟到事件的离线穿越，真实样本还需要 ingest/feature-effective time。

## 3. S2：时间与行为 token

一种可实现编码：

\[
z_t=W[e_i(i_t);e_a(a_t);\log(1+\Delta t_t/\tau);e_c(c_t)].
\]

不同时间定义不能混用：

- `request_time-event_time` 表达相对新鲜度；
- `event_time[t]-event_time[t-1]` 表达行为节奏；
- 内容年龄表达供给生命周期；
- 序列 index 表达相对顺序；
- 原展示位置表达当时的曝光条件。

最后一项与 [展示位置消偏](POSITION_DEBIAS.md) 有关，不能把前四项删掉当作去偏。时间量纲需要明确，秒/毫秒错误足以让所有长期行为被衰减掉。

### 3.1 多行为不是给所有行为乘一个分数

点击、有效观看、完播、复播、点赞、收藏、关注、快划和显式负反馈具有不同语义。可以共用内容表但使用 action embedding；也可分别编码正向/负向历史，再由门控融合。

显式屏蔽需要过滤层尽快生效，不只交给 embedding 学习。一次快划的置信度低于明确“不感兴趣”；无播放机会的事件不应作为兴趣负例。

### 3.2 时间偏置

注意力可加入先验：

\[
l_t=q^TW_kz_t/\sqrt d-\lambda\Delta t_t/\tau,\qquad\lambda=softplus(\rho).
\]

这是新鲜度归纳偏置，**不是展示位置消偏**。固定单一衰减率会抑制低频稳定兴趣；可比较长短期独立衰减、时间桶、截断与无衰减。时间特征已经进入 token 时，再加先验也可能重复强化近期行为，要单独消融。

新增 `TimeAwareSessionEncoder` 已包含 action token、log-age 特征与可学习正衰减；它只实现一个清晰的候选方案，不代表最优。

## 4. S3：短期编码的优化阶梯

| 阶梯 | 结构变化 | 要验证的假设 | 成本与风险 |
|---|---|---|---|
| S3.0 | 时间衰减池化 | 近期权重本身是否已经足够 | 最低成本强基线 |
| S3.1 | GRU/LSTM | 行为顺序是否提供额外信息 | 顺序计算、错误会话会混淆状态 |
| S3.2 | 循环 + 多头注意力 | 同一会话内多个子意图是否有增量 | 参数与算子更多，不增加输出 query 数 |
| S3.3 | 因果 Transformer | 更复杂依赖和并行训练是否有价值 | `L²` 交互、位置/时间处理与缓存 |
| S3.4 | HSTU/高效长序列 | 当前结构处于质量—成本瓶颈 | 需等预算与实际硬件对照，不能只比更大模型 |

只聚合全部“请求前已发生历史”预测下一项时，历史内部双向注意力可以合法；若在一次前向中对每个位置监督 next-item，必须屏蔽未来或逐前缀计算。两者不能混称同一种训练。

### 4.1 辅助目标

可增加 next-action、next-item、有效观看阈值、会话意图一致性等辅助任务。辅助标签也必须成熟且可归因；不要使用请求后完整会话编码作为请求前输入。给所有历史直接套 next-click 可能强化点击偏差，需要检查消费质量与位置校正。

## 5. S4：长期记忆不是无限扩展最近列表

当前基线的 long 仅是截断历史中不属于最后窗口的部分，并不是半年长期画像。真正长期路线可并行比较：

1. 多时间窗口统计和衰减池化；
2. 按日/会话先编码，再聚合 session 表示；
3. 主题/作者聚类与每兴趣摘要；
4. reservoir/分层采样，保护低频稳定兴趣；
5. 检索式历史记忆与更长序列底座。

**召回用户塔的限制**：当前候选尚未知，长期历史筛选不能依赖真实待推荐内容或正例。可用用户当前状态、可学习兴趣 query 或场景做筛选；候选相关历史检索更适合后级排序。训练时拿正例找历史、服务时无法复现，会造成信息条件错配。

长期分支应保留内容语义与行为强度的置信度，控制重复曝光强化。只有反复被系统展示的主题多，不代表用户兴趣一定更强。

## 6. S5：融合、空分支和不确定性

\[
g=\sigma(MLP[s;l;e_u;c;\log(1+n_s);\log(1+n_l)]),
\quad u=g\odot s+(1-g)\odot l.
\]

除了 gate 分布，还要看分支可用性：只有短期时不应分配一半质量给空长期；两者都空时回退静态用户或新用户通道；低置信短期不应立刻推翻稳定兴趣。

新增组件显式构造真实 session mask、长期 mask，强制只有短期时 `g=1`，并在全空时回退用户向量。历史 token padding 的 softmax 质量为 0，不产生虚假均匀行为。

长时间离开后再次请求，最新历史会话也可能已经结束：`build_sequence_features` 会提供 `current_session`。应传给编码器的 `current_sessions`，使当前短期为空、长期可用并强制 `g=0`。不传时编码器默认将最后观测会话当作当前会话，这只是接口回退，不应在真实接入中忽略。

门控饱和监控包括各切片的均值/分位数、分支范数、梯度和去掉分支的效果。高 gate 不等于短期因果贡献；可能由表征尺度或数据缺失驱动。

如果多个长期兴趣压缩仍然丢失，可把短期向量和长期多兴趣分开检索，再融合配额；这会增加 query 与管理成本，应与单向量方案在相同最终 N、总检索量和服务预算下分别比较。

## 7. S6：训练信号、负例与曝光偏差

召回训练的正例来自已经发生的选择。点击正例受展示机会与位置影响；消费正例又受起播、加载和长度影响。位置校正针对特定观察机制，不应与热门降权、sampled-softmax 采样校正或时长长度调整混为同一权重。

随机负例便宜但容易；曝光未消费更接近边界，却可能未被检查；困难负例可能包含用户其他真实兴趣。多行为模型应明确每种样本的标签、观察窗口、置信度与损失位置，而不是把所有权重直接相乘。

新增 `positive_weighted_softmax` 可作为已知 examination propensity 下的正例损失组件，但**尚未接入现有 `Retriever.loss` 和六模型数据协议**。在没有位置/propensity 日志时，不从历史 index 猜权重；当前 18 次训练报告仍是未加该校正的原基线。

## 8. S7：服务与增量状态的优化

| 项目 | 可以缓存什么 | 必须失效/重算的情况 |
|---|---|---|
| 静态用户 | 低频属性/部分长期表示 | 特征、embedding、模型版本变化 |
| 循环状态 | 同一模型下、连续事件前缀的状态 | 会话重置、迟到插入、历史修改/删除 |
| Attention K/V | 满足一致因果/位置定义的旧前缀 | 双向编码追加、位置重排、相关时间偏置改变 |
| 召回结果 | 短时间预取候选 | 新反馈、强负反馈、内容下架和准入变化 |

request-relative age 每次改变，若它直接进入 key，旧 K/V 不一定可复用；滑动窗口导致绝对位置变化也可能使缓存失效。不能把标准 LLM 的 cache 方案原样搬来就承诺实时性。

单向量 SDM 的多头注意力不意味着 K 次 ANN；多兴趣方案才会增加有效 query 数。压测需要同时记录编码、索引访问、融合、排队与反馈新鲜度，不只报一个算子延迟。

## 9. 可实施的实验工作包

| 工作包 | 代码/数据交付 | 首要对照 | 退出条件 |
|---|---|---|---|
| SEQ-01 | `build_sequence_features` + 真实 ingest/as-of 管线 | 固定 N / gap / 产品 session | 无未来穿越，按场景可解释的边界 |
| SEQ-02 | 时间与多行为 token | 同字段无时间/无 action | 兴趣切换和负反馈切片有增量 |
| SEQ-03 | 可用性门控 | 当前 `SessionGateRetriever` | 空分支路径正确，整体与冷启动不退化 |
| SEQ-04 | 会话分层/长期记忆 | 同预算最近 N 历史 | 低频兴趣增益不是单纯增加候选量 |
| SEQ-05 | 校正正例目标 | 同模型未校正目标 + 随机曝光验证 | 支持集、ESS、校准和线上护栏通过 |
| SEQ-06 | 状态缓存与增量 | 全量重算等价性 | 输出误差与失效规则明确，P99/新鲜度达标 |

这些不是每项必定增益的承诺。公开 SDM 混合系统 +10% CTR 属于作者特定业务；本仓库 `session_gate` 合成 Recall 均值 26.736% 也不作为新增组件的预期。必须重新训练、控制输入与预算，再做真实用户实验。

## 10. 组件使用与当前验证

```python
import torch
from recommender.retrieval.sequence import build_sequence_features, TimeAwareSessionEncoder

f = build_sequence_features([1, 2, 3, 4], [0, 20, 4000, 4010], 4100,
                            actions=[1, 2, 1, 3], gap_seconds=1800, max_history=4)
encoder = TimeAwareSessionEncoder(dim=32)
# 真实训练时 item_vectors/user_vector 应来自已定义的 embedding/tower。
item_vectors, user_vector = torch.randn(1, 4, 32), torch.randn(1, 32)
output, diagnostics = encoder(item_vectors, user_vector,
    torch.tensor([f['ages']], dtype=torch.float32), torch.tensor([f['actions']]),
    torch.tensor([f['sessions']]), torch.ones(1, 4, dtype=torch.bool),
    current_sessions=torch.tensor([f['current_session']]))
```

测试已覆盖会话在截断前构造、未来事件拒绝、空历史与空分支、mask、梯度及权重。该示例验证接口，不是新训练模型。接入真实流水线还需动作字典、可推荐目录、版本包和实验配置。
