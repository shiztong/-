# 本仓库实际运行结果：六模型 × 三种子

运行日期：2026-11-04。**这是实际执行的合成数据训练结果，不是原论文复现、业界线上结果或本业务收益预测。**没有真实用户数据、线上 A/B 或 GPU 服务压测。

## 1. 可复现设置

- 配置：[cpu-smoke.json](../../configs/recall/cpu-smoke.json)。
- 数据：固定 data seed=17，96 用户、240 内容、每用户 32 个不重复事件，合成稳定兴趣与后段意图切换；目录起始时即存在。
- 切分：按 0 基索引，训练目标为每用户事件 1–29，验证为事件 30，测试为事件 31；输入始终是目标之前的历史。训练 2,784 个样本，验证/测试各 96 query，时间边界见原始报告。
- 训练：seed=17/18/19，12 epochs，32 维，K=4，Adam lr=0.003，batch=64，full-catalog softmax；默认不输入类别字段。
- 选模：每 seed/模型按验证 Recall 选 checkpoint，平分取最早 epoch；测试标签不参与选模。
- 环境：Python 3.12.14、PyTorch 2.5.1+cpu、CPU 单线程。详细运行元数据、权重哈希、逐轮日志见 [原始结果 JSON](evidence/synthetic-results.json)。本轮 NumPy 固定为 1.26.4；首个训练进程在其安装前启动，所用代码没有调用 NumPy。
- 检索：全目录精确点积；多兴趣取有效头 max；屏蔽历史已看及 padding。每用户单个新颖目标，因此本协议 Recall=HitRate。

## 2. 真实测得的结果

表中的 ± 是 **3 个训练 seed 的样本标准差，单位为百分点**，不是置信区间。三次使用相同测试用户和目标，不能当作 288 个独立 query。

| 本地实现 | 参数量 | seed17 Recall@10 | seed18 | seed19 | Recall 均值 ± seed波动 | NDCG@10 均值 |
|---|---:|---:|---:|---:|---:|---:|
| `mf` | 10,816 | 5.208% | 5.208% | 7.292% | 5.903% ± 1.203 | 0.02208 |
| `pooled` | 17,056 | 17.708% | 19.792% | 27.083% | 21.528% ± 4.923 | 0.09835 |
| `session_gate` | 35,040 | 29.167% | 21.875% | 29.167% | 26.736% ± 4.210 | 0.12067 |
| `mind_ref` | 13,920 | 12.500% | 16.667% | 17.708% | 15.625% ± 2.756 | 0.07257 |
| `comirec_sa_ref` | 18,660 | 9.375% | 8.333% | 11.458% | 9.722% ± 1.591 | 0.04319 |
| `comirec_dr_ref` | 143,968 | 13.542% | 9.375% | 5.208% | 9.375% ± 4.167 | 0.04278 |

这些实现共享同一目录、时间切分、主要 loss 与超参数起点，但**没有匹配模型总参数、系统调优或固定训练计算量**，不能把表解释为普适模型排名。生成器本身包含意图切换，也会影响相对表现。单 seed 的测试分辨率是 1/96≈1.04 个百分点。

## 3. 从运行中能得到的工程结论

1. 六模型训练、选模、导出、精确检索与查询链路已经实际执行，不是伪代码或仅做有限差分。
2. 多兴趣没有自动胜过池化模型。不能用“升级 MIND/ComiRec”替代对数据、假负例、头级贡献与预算的分析。
3. DR 的训练拟合更强并不意味着测试更好。例如 seed17，末轮训练 loss 从首轮 5.7375 降到 1.2857，验证选中的 checkpoint 测试 Recall 为 13.542%；池化末轮 loss 从 5.8665 降到 3.8967，验证选中的 checkpoint 测试 Recall 为 17.708%。训练轨迹末轮与被选 checkpoint 不一定相同，具体 epoch 在 JSON 中记录。这提示容量与过拟合需要研究，**不证明原始 ComiRec-DR 不如双塔**。
4. 18 个运行的训练 loss 均下降；这验证了可学习计算链路，但仍不构成泛化或业务收益保证。
5. 本轮没有 ANN：不引用这个小目录耗时来预测百万内容库的吞吐。日志中的 `exact_batched_evaluation_seconds` 包含批量评分与 Python 评价，不是线上 P99。

## 4. 导出查询的实际证据

[query-example.json](evidence/query-example.json) 保存了 seed17 `session_gate` 的一次实际 checkpoint+index 加载查询，输入为 user=1、history=[1,2,3]。它是接口 smoke payload，不是质量评价样本。查询结果排除了 0/1/2/3，并通过 checkpoint/index 一致性检查。

模型权重与数据保留在本环境的 `artifacts/recall-demo/`，该目录被 Git 忽略；仓库提交的是源代码、配置和带哈希的结果，不依赖提交模型二进制。换一个新目录执行一键命令可重新训练；不同硬件或版本可能产生数值差异，权重文件字节哈希也不保证跨运行相同。

## 5. 下一轮如何变成真实选型依据

用真实全局时间窗、有效消费标签和可推荐目录替代生成器；加入更强的单向量对照、相同特征与预算控制；对多兴趣分别固定最终 N 和总检索预算；加入 ANN 实测与状态更新延迟；最后通过线上用户随机实验验收。
