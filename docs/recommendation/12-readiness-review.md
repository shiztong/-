# 12 对现有方案的反思与落地审查

状态更新（2026-11-04）：下文保留本轮实现前的缺口审查。现在已增加六模型召回训练、精确向量索引导出与查询、合成数据三种子报告，见 [当前召回入口](../recall/README.md)。真实数据、ANN、生产服务及线上收益等缺口仍未完成；不再将下文“无训练实现”等历史描述当作当前全部状态。

结论：当前仓库是一个可运行的协同过滤教学服务，加上深度模型设计资料；不是生产信息流推荐系统。09–11 已经明确部分模型的前向结构，但还缺少真实数据、训练实现、分布式参数存储、在线特征和实验设施，不能据此承诺上线收益。

本轮补充的证据、架构、路线和评估方法，目的是使下一步工程可执行；不等于这些能力已在本仓库实现。原有 `5` 项程序测试只能验证教学服务，不能验证深度模型或生产链路。

## 2. 对原模型方案的具体修正

### 2.1 不把模块清单当作最优架构

DIN + DCN + MMoE + ESMM 是可研究的组合，不是默认全量开启的生产配置。它同时引入候选历史交互、特征交叉、任务共享和漏斗约束，收益归因困难、训练与推理成本叠加。

修正：建立统一输入和多任务 MLP 基线；先验证历史是否提供增量，再决定 DIN/长序列；确认任务负迁移后再比较 MMoE/PLE；漏斗关系成立时才引入乘积约束。所有对比固定数据、预算和评价支持集。

### 2.2 示例字段数和网络宽度没有数据依据

09–11 的 `20` 个字段、`L=100`、`128` 维用于说明张量接口，不是容量规划。真实选择应基于 ID 基数、历史长度分位数、曝光规模、长尾比例和在线候选量。不能根据示例数字直接申请服务器。

修正：先发布数据剖析，再运行 `L∈{50,200,1000}`、宽度和负例预算的缩放实验；将 FLOPs、峰值显存、P99 和新鲜度作为约束。数值网格仅为实验示例。

### 2.3 时长 hazard 不是已经被本项目验证的行业标准

11 的首轮退出/完播/复播建模是一种可解释设计，不能因为数学自洽就认为优于分桶或回归。没有完播、主动退出、播放器中断及观察终止事件时，其删失标签无法可靠构造。

修正：现有日志只能支持最终时长时，先做稳健回归和分桶；补齐状态事件后再试 hazard。KuaiRand 的丰富反馈不自动等于存在完整删失标签；缺失的事件不得推测成事实。

### 2.4 “去偏”必须有识别条件

长度分层、残差、IPS 和漏斗联合建模各自解决不同问题，不能统称消除偏差。内容长度可能是用户真实偏好；旧策略决定谁看见内容；点击后标签又有选择性。

修正：为每个偏差画变量关系和时间顺序，说明随机化来源、可观测变量、支持集及无法识别部分。没有策略概率不开展任意目标策略的 IPS 收益宣称。

### 2.5 实时训练并非越快越好

实时反馈更新、用户状态更新、Embedding 更新和全模型训练是四个不同问题。分钟级模型追逐短期噪声，还可能把迟到负例学成真实负反馈。

修正：先实现用户状态与新内容索引更新；全模型先按成熟窗口周期训练。只有热点响应瓶颈和日志成熟度明确后，再试增量训练，并保留历史重放与版本回滚。

### 2.6 单请求精排收益不等于整个系统收益

更重模型可能让粗排候选更少、排队更久、超时更多；更高离线 NDCG 可能在线失效。用户兴趣刷新变慢也可能抵消模型增益。

修正：同预算与同效果两条 Pareto 曲线都要报告，比较质量、成本、延迟、新鲜度；把特征、检索、网络与排队纳入端到端服务预算。

## 4. 可执行的阶段门槛

每个阶段都要求负责人、产物与退出条件；时间仅是有人员与数据的前提下排期参考，见 14。

1. **数据可用**：曝光与行为可追溯，关键缺失率和迟到比例有测量；没有此证据不进入收益实验。
2. **离线可复现**：基线与候选模型统一时间切分、评价集合、随机种子与版本记录。
3. **服务可承载**：回放峰值负载，端到端 P99、错误率和新鲜度达到已批准 SLO。
4. **实验可识别**：随机化、样本量、护栏、归因、回滚全部预注册。
5. **收益可持续**：主指标区间、经济门槛和长期护栏达标，且不是流量结构变化造成。

未提供真实日志、硬件和业务基线，因此当前能完成“方案与评估工具可执行”，不能宣称“生产系统已可上线”或给出真实收益百分比。
