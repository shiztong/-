# 03 粗排与粗精排协同

## 1. 粗排的任务是保留决策空间

假设召回数千候选，精排只能处理其中数百条。数量仅为示例，真实预算取决于延迟、并发、序列长度和算力。粗排需在相同请求预算下尽量保留最终高价值候选。

单看粗排 AUC 不够：大量容易区分的负例会让 AUC 很高，但模型仍可能系统性淘汰长尾兴趣或新内容。

## 2. 模型结构选择

### 轻量双塔增强

预计算内容表示与请求级用户表示后，为候选计算：

\[
h_i=[e_u;e_i;e_u\odot e_i;|e_u-e_i|;x_{stat};x_{recall}],\quad s_i=MLP(h_i).
\]

比单纯点积更有交互能力，也比完整候选相关长序列 Attention 便宜。内容端统计若实时变化，应与静态缓存表征分开输入，避免缓存失效成本过高。

### 轻量交叉网络

将少量用户、内容、上下文特征输入低层数 DCN 或小型 DNN。序列用请求级池化，或仅对有限近期历史计算轻量候选匹配。取舍重点是候选数乘以候选侧计算成本。

列表页至少保留点击和消费两个任务；视频流至少考虑有效播放/快划及时长代理。粗排只学 CTR，精排学消费价值，会造成目标错位。

## 3. 精排蒸馏

令教师、学生在同一请求候选集 \(S\) 上的分数分别为 \(z_i^T,z_i^S\)。列表蒸馏为：

\[
p_i^T=\operatorname{softmax}_{i\in S}(z_i^T/\tau),\quad
\mathcal L_{KD}=\tau^2\sum_i p_i^T\log\frac{p_i^T}{p_i^S}.
\]

\[
\mathcal L=\alpha\mathcal L_{label}+\beta\mathcal L_{KD}+\gamma\mathcal L_{pair}.
\]

成对损失可关注教师认为价值差距大的候选：

\[
\mathcal L_{pair}=\sum_{(i,j):z_i^T>z_j^T}w_{ij}\log(1+\exp(-(z_i^S-z_j^S))).
\]

教师分数必须有可比较的含义。对不同任务的原始 logits 直接求和再蒸馏，可能把校准差异当成业务价值。可以分别蒸馏各任务输出，再结合统一价值目标训练。

### 选择偏差与支持集

线上只有通过旧粗排的候选有精排输出。如果只在这些候选上蒸馏，学生学不到被旧粗排错杀的区域。可离线对采样的更大召回集合运行教师，并覆盖新内容、低频兴趣和各召回来源。

曝光反馈标签与教师伪标签须分开标记。未展示候选没有真实点击结果，不能因为没有点击日志就设为负例。教师也不能恢复其从未学会的兴趣，探索和真实标签仍必要。

## 4. 服务优化

- 请求级缓存用户静态表征，同一请求批量评分候选。
- 使用内容静态向量缓存，实时特征单独拼接。
- 按硬件实测选择批大小、精度与算子融合；量化后重新检查排序与校准。
- 缺失或超时走确定的降级路径，记录降级比例及候选构成变化。

动态候选预算可以依据请求复杂度调整，但需避免某些用户层级长期获得更差模型服务。

## 5. 验收

测教师 Top-K 的保留率、真实优质正例的保留率，以及在固定精排预算下的最终收益；同时按用户、内容年龄、内容长度和召回通道切片。

教师 Top-K 保留率只衡量与教师的一致性，不能替代真实业务指标。比较时应固定候选集合和计算预算，防止把更多算力的收益误归因于模型结构。
