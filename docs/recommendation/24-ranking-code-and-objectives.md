# 24 精排深入研究：DIN、DCNv2、MMoE、PLE 的机制与实现边界

本章使用新增的 [固定源码清单](evidence/deep-study-sources.json)。读取代码不等于复现训练；以下明确区分通用公式、具体代码路径、静态风险与本项目提出的迁移实验。没有对应实测，不填写模型收益百分比。

## 1. DIN：不要把“注意力”三个字当作结构定义

### 1.1 本轮读到的作者 demo

来源 `zhougr1993/DeepInterestNetwork@9765f96/din/model.py`。item 与 category 各 64 维，拼接为 128 维；历史形状 `[B,L,128]`，候选 query `[B,128]`。激活单元输入：

\[
z_t=[q;h_t;q-h_t;q\odot h_t]\in R^{512}.
\]

demo 使用 `512→80(sigmoid)→40(sigmoid)→1`，按历史 mask 后除以 `sqrt(128)`，再在历史轴 softmax，得到加权历史。这是已读 demo 的实际路径，不把它推广为所有 DIN 实现。

论文思想中的局部激活、非归一化加权，以及其他版本的 Dice，都需单独指明。当前 demo 主路径使用 sigmoid，同时保留 Dice 注释/其他文件线索；不能把“DIN 必须 Dice + 非归一化”与这份代码当成完全同一个实现。

### 1.2 归一化与非归一化的区别

softmax 聚合 `u=Σαt ht` 受凸组合约束；非归一化权重的总幅度可以随相关行为数量变化。例：把两个完全相同的行为复制为四个，如果各 logit 相同，softmax 输出不变；固定非归一化权重求和则幅度翻倍。

这不是哪种必然更好：归一化有利于稳定，非归一化可保留行为量，但受历史长度和重复行为影响。应把长度、重复与兴趣强度做对照，不把实现变化隐藏在同一个模型名下。

### 1.3 Attention 梯度说明了什么

令 `α=softmax(a)`、`u=Σαt ht`，则：

\[
\frac{\partial u}{\partial a_t}=\alpha_t(h_t-u).
\]

当某个权重饱和到接近 1，或历史表征本身高度相似时，其他注意力得分梯度可能较弱。高权重不能解释为用户因果偏好，它也可能吸收重复、位置、热门和表征尺度。

### 1.4 在线复杂度不能只报网络层数

候选数 N、历史长度 L、激活隐层 a 时，候选相关激活大致随 `N*L*d*a` 增长；历史 Embedding 与部分投影可复用，候选相关 MLP 仍需计算。分块广播可以降低峰值内存，但未必降低总算术量。

缓存最终用户兴趣向量后给全部候选共享，将丢掉候选相关性，已经不是同一 DIN。空历史应明确回退；对全 padding 直接 softmax 不能让伪历史参与预测。

## 2. DCNv2：低秩投影减少什么，又限制什么

TFRS Cross 固定版本支持全矩阵、低秩、diag_scale 和可选 preactivation。其默认无非线性情况下：

\[
x_{l+1}=x_l+x_0\odot(W_lx_l+b_l+\gamma x_l).
\]

低秩 `W=UVᵀ`，矩阵参数从 `D²` 变为 `2Dr`。`D=488,r=32` 时分别为 238,144 与 31,232，是约 7.625 倍的该部分参数差，不是整网 7.625 倍加速。

低秩限制每层线性映射的秩，但残差、逐元素乘积和多层组合使整网能力并不简单等于“只能学 r 个特征”。多个 Cross 层在无激活等特定条件下可讨论有界阶次交叉；如果开启 preactivation，不能不加条件沿用纯多项式解释。

### 2.1 Stacked 与 Parallel 的区别

- Stacked：Cross 输出再进深层网络，后续非线性可以利用显式交叉结果。
- Parallel：Cross 与 DNN 分别处理同一输入，最后拼接，保留不同路径。

二者参数与梯度路径不同。必须固定输入和预算做比较，不宣称某种拓扑普遍更强。Cross 主干不是序列编码器；用户兴趣信息缺失时，加 Cross 深度也不能恢复不可见历史。

## 3. MMoE：专家共享、门控选择与负迁移

### 3.1 前向与梯度

给共享输入 x，专家 `ej=fj(x)`，任务门控 `gt=softmax(Wt x)`：

\[
h_t=\sum_j g_{tj}e_j,\qquad \hat y_t=head_t(h_t).
\]

对专家输出的总梯度：

\[
\partial L/\partial e_j=\sum_t\lambda_tg_{tj}\delta_t,
\quad \delta_t=\partial L_t/\partial h_t.
\]

它说明多个任务依然共享同一专家，梯度冲突并没有因模型叫 MoE 就消失。对 gate logit `atj`：

\[
\partial L_t/\partial a_{tj}=g_{tj}\delta_t^T(e_j-h_t).
\]

专家高度同质时，gate 缺少可分辨信号；gate 过早集中时，未选专家可能训练不足。应监控各任务 gate 熵、专家使用、任务梯度范数、标签覆盖与切片，而不是只画一个 gate 热图。

### 3.2 已读框架示例的边界

PaddleRec `MMoELayer` 使用单层 Linear+ReLU 专家，每任务一个 gate 与 tower，输出每任务二分类 softmax。它不是 Google 原厂线上结构，不是本仓库此前示例的多层专家加独立 sigmoid 配置。

该源码给同一 gate 的不同输出列使用相同常数初始化，因此初始化时各专家的 gate logit 相同，softmax 为均匀分布。后续可训练打破对称，不能据此说模型永远不学习；但换 Xavier 初始化就已经改变了复现配置，应记录。

### 3.3 什么时候不该用 MMoE

如果任务标签口径错误、点击样本与全曝光标签混淆，MMoE 只会更强地学习错误关系。若任务都高度相关且数据有限，一个共享主干可能足够。需要与参数匹配的 Shared Bottom、多 tower 比较，而不是只和更小单任务网络比较。

## 4. PLE：共享与专属信息怎样逐层交换

第 l 层为每个任务保留表示 `xt^l`，另有共享表示 `xs^l`。任务 t 的 gate 只读取本任务专属专家集合 `Et(xt)` 与共享专家 `Es(xs)`：

\[
x_t^{l+1}=\sum_jg_{tj}^l E_{tj}^l(x_t^l)+\sum_kg_{tk}^{s,l}E_{sk}^l(x_s^l).
\]

此处两个求和对应同一联合 softmax 的分区，不能各自独立归一化后不说明就相加。中间层共享 gate 可以访问全部任务专家和共享专家；最后一层不再需要向后传播共享表示。多层逐步分离，不是简单地给 MMoE 加几个私有 head。

### 4.1 共享带来的剩余耦合

专属专家降低部分直接冲突，但共享专家、前端 Embedding 和输入仍可能受所有任务影响。专属专家太多会提高成本、分散样本，稀疏互动任务更容易过拟合。PLE 不是从理论上保证多任务无负迁移的通用解。

### 4.2 固定代码中必须处理的索引问题

本轮读到的 PaddleRec `SinglePLELayer.forward` 使用 `i*task_num+j` 取任务专家，而按构造与列表布局应为 `i*exp_per_task+j`。当二者相等时该问题被掩盖；当 `task_num=3,exp_per_task=2`，预期任务专家为 `[0,1]、[2,3]、[4,5]`，实际取到 `[0,1]、[3,4]、[6,7]`。若共享专家从索引 6 开始，最后一个任务会读到共享专家模块。

这是固定版本框架示例的静态索引检查，不是 PLE 原论文算法错误，也不是已执行该框架后的性能结论。迁移前需修正/验证，并检查每个任务、专家数、层数配置；不能直接把所有可下载代码当作可信生产实现。

## 5. 把网络、标签、训练与决策分开设计

### 5.1 列表页任务图

已确认点击是消费前提时，可定义 `pQ=pC*pQgivenC`。分享/关注/负反馈是否也依赖点击，需要由产品事件决定。条件时长只在有有效点击和消费机会的样本上监督；标签未成熟应 mask。

当消费为正时，两个 logits 都得到鼓励；当点击率很低时，消费负例对条件消费头的约束可能较弱。即使乘积预测校准，也不能推出条件头在全曝光区域可靠。

### 5.2 视频流任务图

播放、主动退出、完播、额外复播和日志删失分别定义；时长回归/分桶/hazard 是竞争模型，不是必需一起堆叠。只有状态机日志可靠才能实施首轮 hazard。快划、时长和完播有信息重叠，融合重复奖励需对应业务效用。

### 5.3 多任务 loss 的实际合同

\[
L=\sum_t\lambda_t\frac{\sum_n m_{nt}w_{nt}\ell_t(y_{nt},\hat y_{nt})}{\sum_n m_{nt}w_{nt}+\epsilon}.
\]

mask、权重与抽样校正必须逐任务定义。全零有效标签的任务应不贡献梯度；训练任务权重不同于线上价值权重。使用正负样本重采样后，预测的概率需要相应校准。

## 6. 从预测到最终排序：为什么 AUC 更高仍会失败

候选分布由召回和粗排决定；线上融合又使用多个经过变换的输出。AUC 对单调变换不变，但概率校准会影响跨目标融合，所以“每头 AUC 都提升”不能证明最终价值更好。

如果需要递减时长效用，应区分 `E[g(T)]` 和 `g(E[T])`。例如一条内容等概率观看 0 或 20 秒，均值为 10 秒；另一条总是 10 秒，均值也为 10。对 `g(t)=sqrt(t)`，期望效用分别约为 2.236 和 3.162，均值相同但决策可能不同。这是解析例子，不是业务效用的推荐固定函数。

列表页还要处理位置和可见性，视频流要处理预取及会话状态。单条网络在固定日志上的优势，必须通过候选、校准、服务和在线实验链路验证。

## 7. 精排演进的实际顺序

| 瓶颈 | 第一组实验 | 通过后再做 |
|---|---|---|
| 业务目标错位 | 正确标签、曝光口径、价值校准 | 多任务专家或更复杂分布 |
| 候选兴趣匹配差 | DIN 对照池化，相同历史信息 | 长历史检索/序列底座 |
| 高阶交叉不足 | DCN 低秩/全秩、匹配参数 DNN | 门控或更大交互结构 |
| 共享任务冲突 | 任务 mask/梯度审计、Shared Bottom | MMoE、PLE、梯度优化 |
| 在线成本超标 | 请求级复用、分块、蒸馏 | 更长历史与更大参数 |

不得把上表所有结构一次加入，然后只报告最好一个总指标。完整实验合同见 [25](25-falsifiable-experiment-plan.md)。
