# 19 粗排、精排的完整发展路标

精排的发展不是一条“LR → DIN → 大模型”的直线，而是交叉结构、兴趣历史、任务目标和计算范式四条轴共同发展。下面分别给出起点、解决的问题、遗留边界与未来方向。

## 1. 交叉结构轴：从人工组合到自适应交互

| 阶段 | 代表路线 | 核心机制 | 解决的问题与边界 |
|---|---|---|---|
| X0 | LR + 人工交叉 | `sigmoid(wᵀx)` | 可解释、便宜；交叉发现依赖人工 |
| X1 | FM / FFM | 低秩二阶交互；FFM 按字段区分向量 | 缓解交叉稀疏，仍有限于特定阶次/结构 |
| X2 | Wide & Deep、DeepFM、DCN | 记忆与泛化、显隐式交叉 | 组合学习增强；复杂语义和兴趣仍需专门输入 |
| X3 | DCNv2、注意力交互、门控与专家 | 矩阵/低秩交叉、选择性特征路由 | 更灵活，但增益可能来自参数与算力 |
| X4 | token 化特征、共享序列底座 | 将字段与行为放入可扩展交互模块 | 字段异质、数值编码、稀疏表和推理成本需验证 |

### 机制对比

LR 显式交叉如“用户偏好类目 × 候选类目”依赖人工构造。FM 用 `⟨vi,vj⟩` 共享统计强度。DNN 在拼接表征上隐式学习非线性；DCN 则递归将 `x0` 与上一层变换相乘，增加明确的交叉路径。

这些能力可以组合，不应在一张排行榜中忽略特征与参数差异。注意力权重也不天然是可解释的重要性；某些字段被高权重访问，不证明其对用户行为存在因果作用。

**未来问题**：把高基数 ID、连续数值、上下文和多模态语义统一编码，同时保持低成本、长尾学习与缺失鲁棒性。目标不是单纯增加交叉层数。

## 2. 兴趣轴：从一个用户向量到可检索的长期记忆

### I0：统计与池化

类目分布、作者偏好、历史 Embedding 平均/衰减池化可复用、成本低，但抹平顺序和多兴趣。它们应作为强基线，检验新序列模型是否只是增加了原先没有的历史信号。

### I1：候选相关局部激活

DIN 根据当前候选计算历史权重 `a(q,ht)`。解决“同一用户对不同候选应激活不同兴趣”的问题。它可以不建模历史之间的顺序，并非完整序列模型。

成本约随候选数与历史长度的乘积增长。在线复用历史投影，但仍要逐候选计算匹配。下一步不是无条件把历史增长到万条，而是先测候选相关历史覆盖与实际服务预算。

### I2：兴趣演化和序列依赖

DIEN 类路线引入兴趣状态、演化与辅助目标；SASRec 类路线使用 Self-Attention 学习行为依赖。前者侧重兴趣演化建模，后者提供通用序列交互；不是后者简单包含前者所有假设。

在精排中可以先共享历史序列编码，再做候选 cross-attention。多行为编码需区分点击、观看、快划和主动互动，否则行为强度与语义被混淆。

### I3：检索式长序列

SIM 类路线先在长历史中筛选候选相关子集，再进行精细交互。它把“历史有多长”和“在线精细计算多少”分开。筛选阶段的误杀不能被后续 Attention 恢复，因此要单独验收历史检索覆盖。

长期、短期与会话可以分别编码后门控融合；不要把用户所有历史等价地拼进一个列表。时间间隔和行为可用时间往往与网络结构同样关键。

### I4：大规模行为序列与长期记忆

以 HSTU 等为代表的方向研究规模扩展、推荐专用交互和硬件效率；还可研究压缩记忆、分层历史、半局部计算与候选共享。官方证据见 [13](13-industry-evidence.md)，实现边界见 [15](15-frontier-portfolio.md)。

未来重点是“长历史 + 实时会话 + 多行为 + 内容语义”的有效整合，而非历史长度竞赛。缓存失效、时间偏置、候选感知与反馈乱序必须和模型一同设计。

## 3. 目标轴：从点击到可持续消费价值

### O0：单目标 CTR

容易训练与比较，但列表页可能鼓励封面标题，视频流自动播放下 CTR 甚至不是正确入口。曝光定义、位置和样本选择比模型复杂度更先影响结论。

### O1：漏斗与点击后价值

从 `pClick` 扩展到消费、转化或时长。ESMM 类方法利用事件包含关系预测乘积，如 `pEffective=pClick*pEffectiveGivenClick`。必须验证事件关系；卡片自动播放、跨入口消费可能破坏该定义。

消费时长若已按曝光口径预测，不能再乘 CTR。点击后条件模型在未点击区域可能缺乏识别，漏斗约束也不消除所有选择偏差。

### O2：多任务与负迁移管理

共享主干 → 任务 tower → MMoE → PLE 是代表性结构选择，而非每一阶段必然优于前一阶段。

- Shared Bottom：简单、共享充分，冲突时容易相互牵制。
- MMoE：共享多个专家，任务分别门控，适配不同任务组合。
- PLE：共享与任务专属专家分层分离，减少部分负迁移。
- 梯度平衡/投影：优化共享参数中的冲突；与网络专家结构解决的问题相关但不相同。

多任务模型必须先解决标签成熟度、有效 mask、任务损失归一化、采样与量纲。训练权重调梯度，线上融合权重调决策，不能用同一套系数替代。

### O3：时长分布、满意度和负反馈

回归 → 分桶/多阈值 → 分布/生存建模是可比较的建模路线，不是所有公司都按顺序替换。关键变化是从一个均值输出转向描述快划、普通消费、长观看与复播的不确定性。

视频流需联合考虑绝对时长、片长、完成、主动快划、互动、负反馈和播放状态；列表页需关注点击后的价值兑现与秒退。hazard 蓝图依赖可靠事件，不能在缺少删失标记时凭空补标签。

### O4：长期价值与受约束优化

研究更可靠的回访/满意度代理、因果估计、延迟归因与长期策略。将次日留存标签复制给当天每条内容不能自动形成因果学习；多目标加权也不自动得到长期最优。

未来方向应是密集短期监督与长期随机实验相结合，同时限制负反馈、质量风险和供给伤害。没有可识别实验时，长期模型只作为待验证估计器。

## 4. 计算范式轴：从单候选计算到请求级共享

| 路线 | 性质 | 需验证 |
|---|---|---|
| 独立 pointwise | 各候选单独输出分数 | 便宜稳定，但忽略候选关系 |
| pairwise/listwise 训练 | 优化候选相对顺序或集合损失 | 训练目标变了，不代表在线已建模列表交互 |
| 请求级共享编码 | 历史和用户表征复用 | 候选数、批处理、缓存一致性 |
| target-aware 序列 | 历史与目标以受控交互结构联合建模 | mask、未来泄漏、端到端吞吐 |
| 列表/序列决策 | 输出组合或逐步选择 | 反馈选择偏差、合法候选与决策成本 |

“生成式精排”“生成式推荐”在不同资料中可能表示行为序列建模、生成内容 ID 或生成整个列表，不能不加定义地比较。

## 5. 粗排的独立路标

### P0 → P1：从规则到轻量模型

使用统计、召回分数、用户/内容向量与少量交叉，从大候选中选出可承担的精排集合。优化目标首先是同预算保留高价值内容，而不只是总体 AUC。

### P2：目标对齐与精排蒸馏

引入与精排一致的任务，利用教师分数、pairwise 关系和请求内分布蒸馏。离线对更广召回集合运行教师，减轻只在旧粗排支持集上训练的局限。

### P3：粗精排协同和自适应计算

研究共享 Embedding、共享用户编码、多出口、按请求复杂度动态分配候选和算力。需防止某些用户群长期获得较差服务，并区分共享带来的维护耦合与计算节省。

### P4：部分阶段融合

当模型与服务效率足够好，可研究减少阶段边界或扩大联合建模集合。但全库复杂交互通常仍不可直接承担；阶段数量减少不是目标，价值与成本前沿才是目标。

## 6. 我们应如何选路线

| 诊断证据 | 优先路线 | 不应首先做 |
|---|---|---|
| CTR 高而消费差 | O1/O3、封面兑现、价值融合 | 单纯加深 CTR 网络 |
| 当前会话跟不上 | I2、实时状态 | 只扩大离线长期模型 |
| 长期兴趣被遗忘 | I3/I4、多兴趣/长期记忆 | 无限提高最近行为权重 |
| 多任务互相伤害 | 标签审计后试 MMoE/PLE/梯度方法 | 直接新增更多任务 |
| 好候选精排前消失 | P2、支持集覆盖 | 只优化精排 AUC |
| 离线好但成本高 | 请求复用、量化、蒸馏与预算优化 | 无限制扩大模型 |
