# 09 召回模型实现蓝图：从样本到向量索引

本文给出一个完整的可实现设计，而非某篇论文的原样复现。维度与超参数是便于复现的实验起点，不是行业固定配置。伪代码采用 PyTorch 风格，不是仓库已提供的训练实现。

## 1. 训练样本的精确定义

每个样本为 `(user_snapshot, context, history, positive_item)`，历史截断于目标曝光前。列表页分别建立“点击”和“点击后有效消费”样本集；视频流使用真实起播后有效消费样本，并保留快划与播放失败标记。只用点击正例训练的模型不能宣称优化了满意度。

先采用每个样本一个正例，其他批内内容为候选负例。一个用户同一时间窗有多个正例时，可选择多正例目标或将已知其他正例从负例中屏蔽；不能让它们同时作为强正例和强负例。

| 张量 | 形状 | 语义 |
|---|---|---|
| user_fields | `[B, 8]` | 8 个离散字段，分别查表 |
| user_stats | `[B, 32]` | 训练期拟合变换后的统计及缺失指示 |
| history_item | `[B, L]` | 历史内容标识 |
| history_action/gap | `[B, L]` | 行为类型与距请求时间分桶 |
| history_mask | `[B, L]` | `True` 表示真实行为，非 padding |
| positive_fields | `[B, 6]` | 目标内容、作者、类目等离散字段 |
| positive_semantic | `[B, 256]` | 离线内容语义向量 |
| positive_stats | `[B, 16]` | 目标曝光前已可用的统计特征 |

示例取 `L=100`，保留最近历史；需要更长期兴趣时增加独立长期分支，而不是无条件无限延长序列。ID 字段的 0 留作 padding，OOV 使用独立标识。

## 2. 内容塔：必须能独立离线运行

6 个离散字段各映射 32 维，得到 192 维。语义向量经 `Linear(256,128) → LayerNorm → GELU`；统计特征为 16 维。拼接得到 336 维：

```text
[6 × 32; 128; 16] = 336
→ Linear(336,256) → LayerNorm → GELU
→ Linear(256,128)
→ L2 normalize
```

内容统计变化过快时，不宜频繁重算整个内容索引。可先移除动态统计建立稳定内容塔，将动态质量放到粗排；是否加入内容塔要结合索引更新能力验证。内容 ID dropout 的含义是训练时将部分内容 ID 替换为 OOV，但保留作者、语义等，以增强冷启动能力。

新内容没有 ID 训练历史，但可使用 OOV ID、已知作者和语义分支生成向量。已有内容仍可能主要依赖 ID，因此必须单独测零曝光内容，而非只看全量 Recall。

## 3. 用户塔：序列编码与请求级聚合

每个行为 token 使用内容 ID 64 维、行为类型 8 维、时间间隔 8 维，拼接 80 维后投影到 128 维，加位置编码。经过两层 Pre-LN Transformer，4 个头，每头 32 维，FFN 隐层 512。

一层为：

\[
X'=X+Dropout(MHA(LN(X))),\quad
X''=X'+Dropout(W_2 GELU(W_1 LN(X'))).
\]

采用自回归 next-item 训练时使用因果 mask；若只把完整的请求前历史聚合后预测一个目标，历史内部双向 Attention 也合法。二者的信息条件不同，不能混用训练描述。

masked mean 得到 128 维历史表示，空历史返回专门的可学习向量或零向量加空历史标记。8 个用户字段各 16 维，加 32 维统计，用户塔输入为 `128+128+32=288`：

```text
288 → Linear(288,256) → LayerNorm → GELU
    → Linear(256,128) → L2 normalize
```

平均池化易复现但可能稀释近期兴趣，可与最后有效状态、时间衰减池化比较。短视频可按会话边界增加 session embedding；列表页可加入入口与场景字段。

## 4. 批内对比学习：准确区分目标含义

令 `U,V` 均为 `[B,128]`，`logits = U @ V.T / temperature`，正例在对角线。基础对比损失：

\[
L=-\frac1B\sum_b\log\frac{e^{s_{bb}}}{\sum_{j\in A_b}e^{s_{bj}}}.
\]

`A_b` 包含对角正例和允许的负例；排除同内容重复列、用户已知其他正例等。下列伪代码采用单正例屏蔽策略，不是无偏全库 softmax：

```python
u = user_tower(batch)                    # [B,128]
v = item_tower(batch.positive)            # [B,128]
logits = u @ v.T / temperature            # [B,B]
allowed = build_negative_mask(batch)     # 保留每个对角线正例
logits = logits.masked_fill(~allowed, -float('inf'))
loss_each = cross_entropy(logits, arange(B), reduction='none')
loss = (loss_each * example_weight).sum() / example_weight.sum().clamp_min(1)
```

如果一个批次全部是相同内容，则屏蔽后没有有效负例，损失为零，不能据此认定训练正常。监控每行有效负例数、正例排名、温度、向量范数及热门集中度。

温度可先试 0.05、0.1、0.2；过低会放大困难负例和噪声，过高削弱区分力。若温度可学习，应约束范围。批大小变化会改变负例集合和目标难度，不能直接比较损失值。

多正例版本可用 `-log(sum(exp(s_positive))/sum(exp(s_allowed)))` 表达集合命中目标，也可对每个正例分别取对数再平均；两个目标不同，应明确选择。若要 sampled-softmax 校正，必须记录真实采样机制，再使用对应估计器，不能在上述任意屏蔽目标上随手减全局频率。

## 5. 多兴趣扩展：完整形状与聚合

以历史编码 `H:[B,L,128]` 和 `K=4` 个可学习查询 `Q:[4,128]` 构造：

\[
A=softmax_L(QH^\top/\sqrt{128}),\quad E=AH\in\mathbb R^{B\times4\times128}.
\]

padding 在 softmax 前屏蔽，空历史单独处理。每个兴趣向量可以与用户静态特征拼接后投影归一化，得到最终 `[B,4,128]`。候选打分为：

\[
s_{bj}=\max_k e_{bk}^\top v_j/\tau.
\]

max 只向获胜兴趣头传递主损失梯度，可能导致某些头长期不更新。可使用平滑 logsumexp 聚合、兴趣负载监控和轻量多样性正则作为实验项；平滑训练而采用 max 检索时需检查不一致。

不要把多样性损失直接设得很大，否则会强迫单一兴趣用户产生虚假兴趣。监控每头覆盖内容、命中贡献和空转比例，按同等总检索候选量与单向量比较。

## 6. 训练配置与故障定位

起点可用 AdamW、稠密学习率 `1e-3`、warmup、梯度裁剪、LayerNorm，按验证集选权重衰减和早停。真实大规模稀疏表需单独考虑稀疏优化器、分片和冷 ID 更新；不是所有稀疏梯度优化器都兼容 AdamW。

| 现象 | 优先检查 |
|---|---|
| Loss 很低，Recall 无增益 | 重复正例泄漏、负例过易、目标错位 |
| 全召回热门内容 | 训练正例频率、ID 范数、负采样、热门覆盖 |
| 新内容向量聚成一团 | ID 依赖、语义分支未训练、OOV 处理 |
| 离线好线上差 | 索引版本、特征延迟、用户/内容归一化不一致 |
| 多兴趣不如单向量 | 兴趣头塌缩、预算不公平、用户历史过短 |

## 7. 服务与必做消融

导出用户塔与内容塔两个独立产物；全量内容编码后建索引，新增内容增量入库，删除内容及时移出。用户模型、内容向量和索引必须记录版本映射。重新训练改变向量空间后，不能默认兼容旧索引。

单向量先在小集合上做精确点积 Top-K 验证，再测 ANN 相对精确结果的召回损失。多兴趣分别检索后按最终 max 相似度合并去重，已看、屏蔽和过期过滤后要检查候选是否足够。

必做消融：ID-only vs 内容语义；平均池化 vs Transformer；单兴趣 vs 多兴趣；点击正例 vs 有效消费；静态历史 vs 实时更新；精确检索 vs ANN。分别报告时间切分 Recall、新内容覆盖、最终消费增益和请求成本。
