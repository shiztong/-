# 16 收益评估、实验设计与经济验收

## 1. 三类数字必须分开

1. **公开报告**：例如 13 中官方 HSTU 的离线 HR 和特定硬件性能。本项目没有复现，不能外推业务收益。
2. **本业务测量**：需要真实基线、随机实验、置信区间和成本账单。目前未提供。
3. **规划假设**：以下情景用于敏感性和盈亏平衡分析，不是模型预测、承诺区间或投资回报保证。

不能把召回 +2%、排序 +1%、重排 +1% 相加成为总收益。模块间候选和反馈重叠，最终需联合实验；各阶段的离线指标也不是同一个量纲。

## 2. 从能力改善到业务价值的证据链

| 项目 | 技术中间指标 | 必须继续验证 | 决策证据 |
|---|---|---|---|
| 召回增强 | 有效消费 Recall、独有候选 | 精排是否选择、用户是否消费 | 端到端消费/满意度 |
| 粗排蒸馏 | 高价值候选保留率 | 教师是否可靠、总算力是否增加 | 固定预算下在线收益 |
| 长序列 | 分层 NDCG/校准、长期兴趣覆盖 | 新鲜度、延迟、缓存失效率 | 净收益及回访护栏 |
| 多模态 | 新内容语义匹配 | 零曝光探索中的真实反馈 | 新内容及总体收益 |
| kernel/低精度 | 单算子/整栈耗时 | 服务排队、特征与网络成本 | 同质量端到端资源节省 |
| 重排/探索 | 覆盖、重复率、发现率 | 是否只是无关内容变多 | 满意度、长期回访与供给 |

计算优化可用 Amdahl 规律约束预期：被优化部分占端到端耗时比例 `f`，局部加速 `s`，理想整体加速为 `1/((1-f)+f/s)`。若 attention 仅占 30%，局部快 2 倍，理想整体约 1.18 倍；真实服务还受批处理、排队和硬件利用率影响。

## 3. 经济模型

以有效观看分钟为例，假设 DAU 和用户结构短期稳定：

\[
\Delta M=DAU\times M_0\times\delta,\qquad
\Delta V=\Delta M\times v,
\]
\[
C=C_{serve}+C_{train}+C_{data}+C_{engineering}/H,
\quad Net=\Delta V-C.
\]

`v` 是每个增量分钟的增量贡献价值，需要业务验证，不是全站营收除以时长的自然等价物。广告负载、转化、留存和成本可能非线性。非商业化业务可使用满意度/留存约束下的单位效果成本，不必强行货币化。

盈亏平衡相对增益：`delta_break_even=C/(DAU*M0*v)`。若单位增量价值未知，应输出敏感性曲线或待测项，不应编造真实 ROI。

### 示例：所有输入均为假设

DAU=100 万，基线 30 分钟/人/日，每增量分钟贡献 0.002 元；新增服务/训练/数据成本分别为 300/80/20 元/日，工程投入 18 万元按 180 天摊销。总增量成本 1,400 元/日，盈亏平衡相对增益约 2.33%。

| 假设相对时长变化 | 增量分钟/日 | 增量贡献/日 | 扣增量成本后/日 |
|---|---:|---:|---:|
| -0.5% | -150,000 | -300 元 | -1,700 元 |
| 0 | 0 | 0 元 | -1,400 元 |
| +1% | +300,000 | +600 元 | -800 元 |
| +3% | +900,000 | +1,800 元 | +400 元 |

这说明统计显著的 +1% 也可能经济上不值得。示例没有给各情景赋概率，不能称为期望收益预测。工程摊销与现金支出应分别呈现，不能一边摊销一边再全额扣同一成本。

模型增大还需考虑 GPU 冗余、峰值弹性、双版本索引、教师离线编码、状态存储、通信及长期维护。所有成本以相同时间口径计算，明确是增量还是全量。

## 4. 可执行测算

在仓库根目录运行，无第三方依赖：

```bash
python3 tools/estimate_recommendation_value.py docs/recommendation/evidence/value-scenarios.example.json
python3 -m unittest discover -s tests -p 'test_value_estimator.py' -v
```

脚本输出各假设情景净价值、盈亏平衡增益和简化实验样本量。替换 JSON 中输入，不要把示例作为业务事实。该工具不估计模型成功概率、跨模块叠加收益、长期 DAU 变化或非线性商业化。

## 5. 实验功效：以用户为单位

建议稳定用户分桶，分场景报告，但跨场景可能有溢出：一个用户在列表页发现作者，随后去视频流消费。全用户总价值与场景局部价值都要检查，不要将两处收益重复加总。

对固定窗口的独立用户指标，等分配、近似等方差、双侧检验的样本量近似为：

\[
n_{arm}\approx2(z_{1-\alpha/2}+z_{power})^2\sigma^2/\Delta^2.
\]

示例 `sigma=40` 分钟、绝对 MDE=0.3 分钟、alpha=0.05、power=0.8，需要约 27.9 万独立用户/组。这里的 40 必须是同一固定观察窗口的用户指标标准差；不能把单次播放时长标准差代入用户日指标。

同一个用户观察 7 天不是 7 个独立用户。不能用 DAU×天数简单当样本量；实验持续时间取决于独立用户覆盖、留存窗口、周周期、功效和流量比例。脚本故意不推导日历天数。

重尾时长需检查异常值、稳健估计与用户聚类 bootstrap；预先定义截断会改变目标含义。CUPED 使用实验前变量且需满足条件，可减方差，但收益幅度要实测。

比率指标需要明确分子分母与随机化单位，通常采用用户级聚合、delta method 或合适的 bootstrap。曝光量会被策略改变，不能只看按曝光归一化的指标而忽略用户总量。

## 6. 决策协议

实验前记录：主指标、最小商业增益、功效、分桶、流量、分析窗口、护栏与回滚标准。并行多版本比较需处理多重检验；未经序贯设计反复看显著性后提前停，会增加假阳性。

统计上显著大于零，不等于显著超过经济门槛。若要证明超过盈亏平衡 `delta0`，应检验或估计 `delta-delta0`；相应样本量中的效果间距也应以超过门槛的幅度设计。

上线条件示例：质量、安全、负反馈及 P99 达标；主指标结果满足预注册统计标准；贡献价值保守下界覆盖增量成本；长期回访与供给无明显恶化。具体阈值需业务明确，本文不擅自给真实容忍度。

## 7. 可用于管理评审的一页结论

每个方向输出：证据等级、当前瓶颈、预计机制、所需资源、最大损失预算、首轮实验、经济门槛、失败切片、停止条件。缺乏真实基线的“预期提升 3%–5%”不能进入承诺表；可登记为待验证假设，但不得作为已具可信度的预测。
