# 23 召回深入研究：结构、梯度、参数、检索与演进条件

本章把“模型是什么”推进到“相同输入如何计算、梯度流向哪里、服务代价来自哪里、怎样证明升级有效”。所有明确到代码的论断均限定于 [22 固定的源码版本](22-model-by-model-evidence-audit.md)，不将某个复现当作整个模型家族。本文的解析计算不是训练结果，不补造线上收益。

## 1. 先统一问题，才能比较模型

设请求前历史为 `E∈R^(B×L×d)`，用户静态特征为 `xu`，候选向量为 `vi∈R^d`，mask 标记实际行为。单向量模型输出 `u∈R^(B×d)`；多兴趣输出 `U∈R^(B×K×d)`。内容塔、负例、训练窗口、评价库和最终候选预算都必须记录。

至少做两类比较：

- **结构控制实验**：相同输入字段、内容编码、损失、样本、负例和服务预算，比较用户编码结构。
- **系统最优实验**：允许各模型调优，比较质量—训练成本—推理成本—新鲜度的 Pareto 前沿。

两种结果不能混称。MF 只接收 ID，另一个模型同时增加标题、作者与半年历史，不能把全部差距归于神经网络。

## 2. MF 与特征化双塔：基线究竟控制了什么

### 2.1 MF 的三种常见目标并不等价

评分回归：`L=Σ(rui-puᵀqi)²+λΩ`。隐式加权矩阵分解：对二元偏好与置信度进行加权平方误差。BPR：

\[
L_{BPR}=-\log\sigma(p_u^Tq_{i^+}-p_u^Tq_{i^-})+\lambda\Omega.
\]

它们的标签空间、负例、目标不同。纯 MF 的参数主要是 `(Nu+Ni)d`，不是“小模型”就一定省内存；海量 ID 表和优化器状态可能远大于用户塔 MLP。

### 2.2 YoutubeDNN 风格的收益来源需拆开

用户历史池化与属性拼接后经过 MLP：`u=f([pool(E);xu;context])`；内容可能只是 ID lookup，也可能扩展为特征塔。已读 DeepMatch 版本属于前者，不应称为对称深层内容塔。

样本 softmax 的用户向量梯度，在一个给定候选集合 `S` 内为：

\[
\frac{\partial L}{\partial u}=\frac1\tau\left(\sum_{j\in S}p_jv_j-v_{i^+}\right).
\]

这个公式忽略归一化层的链式项；若 `u` 来自 L2 normalize，还需乘其 Jacobian。它说明负例决定模型被推离什么，不说明所有 sampled-softmax 都是全库无偏估计。

单向量可能把相距较远的偏好压缩到一个折中方向，但不是数学上不能表达多兴趣。真正问题是固定维度与点积形式下的表达、训练与覆盖损失，需用兴趣切片验证。

**应保留的基线**：ID-MF、池化+MLP、时间衰减池化+MLP。否则 SDM 的增益可能仅来自更好的近期权重，而非完整时序结构。

## 3. SDM：门控融合到底学到了什么

### 3.1 结构分解

作者材料中短期输入按 session/time 组织；短期循环状态经多头 Self-Attention 和用户相关聚合形成 `s`，长期历史按侧信息聚合形成 `l`。用户静态表示 `e` 参与注意力与门控：

\[
g=\sigma(W_g[s;l;e]+b_g),\qquad u=g\odot s+(1-g)\odot l.
\]

`g` 可以是向量，不应将模型简化成一个全局短期权重。对某个用户，品牌偏好可能稳定，类目需求可能快速变化。

### 3.2 门控梯度与饱和

若最终损失对 `u` 的梯度是 `δ`，忽略 `s/l` 经门控输入产生的间接路径：

\[
\partial L/\partial s=\delta\odot g,\quad
\partial L/\partial l=\delta\odot(1-g),
\]
\[
\partial L/\partial a_g=\delta\odot(s-l)\odot g(1-g).
\]

当门控很早饱和到 0 或 1，某个分支直接梯度变小；当 `s≈l`，门控区分也缺少信号。需要监控门控分布、分支范数、有效梯度和去掉分支的消融，不能只看 gate 平均值解释用户心理。

### 3.3 工程与反例

SDM 最终仍输出一个向量，多头不增加检索 query 数。循环计算和历史编码开销在用户侧，内容索引可复用。

会话边界过短会让短期样本不足，过长会混合多种需求；短视频连续滑动不必与电商购物 session 共用定义。应比较真实 session、时间 gap、固定最近 N 条三种构造，避免把人为超参当作用户意图真值。

低活用户的短期分支可能为空；高活用户的新行为可能在服务缓存中不可见。前者是数据路径问题，后者是新鲜度问题，均不能靠增加注意力头数修复。

### 3.4 演进判据

只有在用户状态、样本与预算一致后，SDM 相比衰减池化或简单 GRU 在兴趣切换、有效消费和成本上仍有增量，才值得增加其长期维护复杂度。作者电商收益表只支持选题，不替代视频流实验。

## 4. MIND：路由、label-aware readout 与兴趣塌缩

### 4.1 一次路由迭代

给历史行为 `et` 构造投影 `ût,k`，路由 logits 为 `bt,k`：

\[
c_{tk}=softmax_k(b_{tk}),\quad s_k=\sum_t m_t c_{tk}\hat e_{tk},
\]
\[
v_k=\frac{\|s_k\|^2}{1+\|s_k\|^2}\frac{s_k}{\sqrt{\|s_k\|^2+\epsilon}},
\quad b_{tk}\leftarrow b_{tk}+\hat e_{tk}^Tv_k.
\]

softmax 在**兴趣轴**，意思是一个历史行为如何分配给兴趣；与在历史轴归一化的注意力池化不同。squash 约束胶囊范数，若后续又统一 L2 normalize，范数信息的使用方式会改变，需记录实现。

### 4.2 为什么共享变换需要打破对称

若各兴趣共享变换、初始路由 logits 完全一致，并对所有头执行同样操作，则各头可能产生相同结果。已读 ComiRec 仓库中的 MIND 对照为共享变换，但路由 logits 使用随机初始值；DR 则通过位置/兴趣变换制造结构差异，零初始化 logits 也不意味着所有头完全等价。

这里描述的是具体对照代码，而非断言所有 MIND 版本只能这样初始化。对称性、随机性和种子影响可复现性，模型名本身不包含这些信息。

### 4.3 label-aware readout 与训练服务差异

训练时利用正例 query 聚合或选择兴趣；若 soft readout：`u+=Σk αk vk`；若 hard readout：`k*=argmax(vkᵀvi+)`，仅用获胜兴趣参与主损失。

hard readout 对未获胜的**兴趣表征**不提供直接 readout 梯度，但共享编码与分类器参数仍会更新；不能据此说未获胜头的全部参数永远不变。soft readout 更平滑，也可能让全部头追随热门兴趣。

服务时正例未知，不能用真实目标挑头。应导出有效兴趣，进行检索与合并。动态有效头数与固定物理张量上限可并存，具体公式见 22。

### 4.4 需要测量的不是只有 Recall

每头获胜频率、头间相似度、低频兴趣覆盖、兴趣刷新延迟、各头独有候选及实际有效头数分布都要记录。强制头正交可能制造无用方向；差异正则不应压过推荐目标。

## 5. ComiRec-DR 与 ComiRec-SA：同为 K 向量，为何成本不同

### 5.1 固定源码的参数化差异

本节均指 `THUDM/ComiRec@a576eed` 的 `src/model.py`：

| 项目 | 仓库 MIND 对照 | ComiRec-DR | ComiRec-SA |
|---|---|---|---|
| 历史投影 | 共享 `d×d` 变换后复制到 K 头 | 参数形状 `[1,L,Kd,d]`，位置/兴趣相关 | `d→4h→K` 得注意力 logits |
| 聚合 | 动态路由 | 动态路由 | 历史轴 softmax 后加权 |
| 路由/注意力初始化 | 随机 routing logits | 零 routing logits，但变换不同 | 依赖可学习网络与可选位置表 |
| 中间路由梯度 | 迭代中使用 stop_gradient | 同左 | 无该路由过程 |
| readout | 默认 hard，可改 soft | 默认 hard，可改 soft | 代码 hard argmax |
| 顺序信息 | 共享变换本身不编码顺序 | 变换显式依赖历史位置 | 默认位置 embedding 可开启 |

由此不能把 ComiRec-DR 说成“只是把 MIND 的名字换了”，也不能把 SA 的多组池化称为完整 token-to-token Transformer。

### 5.2 可复算的参数与显存分析

令 `L=256,K=4,d=h=64`，仅比较上表相关模块，不含 ID 表、损失分类器及其他塔：

- MIND 对照共享路由变换：`d²=4,096` 参数。
- DR 位置/兴趣变换：`L*K*d²=4,194,304` 参数，是前者的 1,024 倍。
- SA 两层注意力权重：`d*4h+4h*K=17,408`；加位置表 `L*d=16,384`，合计 33,792，不含 260 个 bias。

这不是论文宣称的性能数据，是按已读源码形状计算的参数量。若其他实现改用共享或低秩变换，数字应重新计算。

DR 字面广播表达式的中间张量可能达到 `B*L*K*d*d`。若 `B=128`、FP32，形状对应约 2 GiB，而权重本身约 16 MiB。编译器可能消除或融合部分中间量，所以这是物化规模估算，不是实测峰值。应检查 profiler，并比较等价 einsum/批量矩阵实现，而不是据此直接采购显存。

### 5.3 SA 的数学性质

\[
A=softmax_L(W_2\tanh(W_1(E+P))),\qquad V=AE.
\]

去掉位置 `P` 后，对历史重排，注意力 logits 和 value 同步重排，输出不变。这证明它在该配置下是集合聚合，不是顺序模型。加入位置后通常打破该不变性，但也不等于学会了间隔、会话边界或复杂转移。

公开实现通过多组池化生成 `K` 个兴趣，没有显式的 `L×L` token-pair attention 矩阵。其关注权重生成成本主要来自每 token 的 MLP 与 `K×L` 聚合，不能按标准 Transformer 的二次长度开销估算。

### 5.4 hard readout 与检索目标

`s(i)=maxk vkᵀvi` 是一个分段平滑的多兴趣打分。不同兴趣获得正例的频率不均，可能出现头饥饿；小语种或小众主题头尤其需要切片检查。将 max 换成 logsumexp 可作为实验，但改变了目标，不得仍称完全复现。

候选合并可加入类目重复惩罚，这属于决策策略，和兴趣抽取是两个消融轴。不能同时增加 K、扩大候选数、增加多样性惩罚后，全部记作 SA 的收益。

## 6. 负例与兴趣覆盖：为什么更大的 K 也会失败

如果批内大量负例来自同一用户的其他真实兴趣，模型会把这些兴趣互相推开；如果全是随机容易负例，模型可能只学热门与非热门区分。需要区分随机、曝光未消费、困难负例和假负例，而不是只汇报总负例数。

训练抽样概率修正、假负例屏蔽、采样标签权重和概率校准分别解决不同问题。必须明确采样估计器，不能在任意对比损失上机械加一个 `-log frequency`。

多兴趣的目标是提高有效覆盖，不是保证每个用户都需要 K 个兴趣。新用户、极短历史或单一意图用户可能没有足够信息分离多个头。

## 7. 同预算评测：K、每头深度与最终候选数

必须分别报告三组实验：

1. **固定最终候选数**：每头检索 N、合并到 N；可能增加实际检索工作量，测其增量价值与成本。
2. **固定总检索结果位置数**：多头共享预算，约每头 `N/K`；可控制部分工作量，但去重后候选可能不足。
3. **固定端到端 P99/资源**：按实测调整每头深度、batch 和有效头数，比较真正可部署前沿。

三者都不能用“QPS×K”概括。还要报告 ANN 相对精确搜索的损失、候选去重率、后过滤不足率和内容刷新延迟。

## 8. 模型演进的可证伪结论

| 研究假设 | 必须建立的对照 | 失败意味着什么 |
|---|---|---|
| SDM 解决短期意图 | 衰减池化/GRU，输入和新鲜度一致 | 复杂长期融合可能没有必要 |
| MIND 解决单向量压缩 | 同输入单向量 + 同候选/资源预算 | 多兴趣可能只是增加检索量 |
| DR 优于 SA | 参数/预算控制、位置控制、种子重复 | 增益可能来自容量或位置而非路由 |
| SA 的位置有价值 | 开/关位置，历史重排探针 | 模型可能并未利用顺序 |
| 大 K 提高覆盖 | 头级贡献与长尾切片 | 兴趣塌缩或无效 query 增多 |
| 新底座适合短视频 | 有效观看/快划目标与在线状态 | 电商离线收益无法直接迁移 |

解析计算可运行 `python3 tools/model_mechanism_probes.py`，输出仅证明所写公式与索引示例的性质，不是推荐效果 benchmark。真实效果证据仍只有 22 中明确注明来源的作者报告，及未来待做的本业务实验。
