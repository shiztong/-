# 10 列表页精排实现蓝图：DIN + DCN + MMoE + 消费漏斗

这是一个组合设计，用来明确模块接口、损失和服务方式；不是对 DIN、DCNv2、MMoE 或 ESMM 任一原论文完整配置的复现。默认真实可见曝光为样本单位，且有效消费必须经过点击。

## 1. 完整张量合同

设训练批大小 `B`、历史长度 `L=100`、统一历史维度 `d=64`。

| 输入 | 形状 | 处理 |
|---|---|---|
| 20 个稀疏字段 | `[B,20]` | 每字段 16 维，拼接 320 维 |
| 40 个数值/缺失特征 | `[B,40]` | 使用已固化的变换 |
| 候选内容语义 | `[B,256]` | 线性投影至 64 维 |
| 正向历史内容与行为 | `[B,L,...]` | 每个行为投影到 64 维 |
| 历史有效 mask | `[B,L]` | 避免 padding 参与 Attention |
| 标签与任务 mask | `[B,T]` | 每任务独立有效性与成熟度 |

DIN 输出 64 维，得到 `x0:[B,488] = [320;40;64;64]`。如果增加特征，必须更新输入维度与模型配置，不能保持硬编码 488。

## 2. DIN：逐元素构造与安全 mask

候选 query `q:[B,64]`，历史 `H:[B,L,64]`。将 query 扩展到历史轴，计算：

```text
cat(H, q, H-q, H*q)     [B,L,256]
→ Linear(256,80) → PReLU
→ Linear(80,40)  → PReLU
→ Linear(40,1)            [B,L,1]
```

这是一个 softmax-normalized DIN-style 变体。可加入时间间隔特征扩展激活单元，但维度也随之变化。

```python
score = activation_unit(H, q).squeeze(-1)       # [B,L]
has_history = mask.any(dim=-1, keepdim=True)    # [B,1]
# 全 padding 行先使用安全 logits，避免 softmax(-inf,...,-inf) 为 NaN
safe_score = score.masked_fill(~mask, -1e9)
alpha = softmax(safe_score, dim=-1) * mask
alpha = alpha / alpha.sum(-1, keepdim=True).clamp_min(1e-8)
h = (alpha[..., None] * H).sum(dim=1)          # [B,64]
h = where(has_history, h, empty_history_vector)
```

若输入使用半精度，应选择该 dtype 可表示的 mask 值，或在 FP32 下计算 softmax。mask 后再次归一化确保 padding 不贡献权重。

同一内容表征可供 query 与历史共享部分表，但行为类型、时间和消费强度仅属于历史侧。query 与历史使用不同投影时，要确保能在同一激活空间交互。

## 3. DCN 与 DNN 并联

以 488 维输入做三层低秩交叉，秩 `r=32`：

\[
x_{l+1}=x_l+x_0\odot(U_l(V_l^\top x_l)+b_l),
\quad U_l,V_l\in\mathbb R^{488\times32}.
\]

每层矩阵参数约 `2×488×32=31,232`，另加偏置；三层约 9.5 万参数。全矩阵每层约 `488²=238,144` 参数，表达能力和成本不同。

并行深层分支 `488→256→128`，激活 GELU。交叉分支输出 488 维，与 DNN 的 128 维拼接为 616 维，再投影到共享表示 `h:[B,256]`。LayerNorm、dropout 是可选实验项，需固定训练/推理模式。

交叉层没有天然的业务解释：某个权重变大并不证明某个用户属性导致点击，应通过特征消融和切片评估判断。

## 4. MMoE：专家、门控与任务头

6 个专家，每个 `256→128→64`，叠成 `E:[B,6,64]`。每个任务独立门控 `Linear(256,6)→softmax`，得到 `g_t:[B,6]`：

\[
h_t=\sum_{j=1}^6g_{tj}E_j(h),\quad z_t=MLP_{64\to32\to1}(h_t).
\]

建议初始任务：点击 `C`、点击后有效消费 `Q|C`、点击后时长、分享、关注、显式负反馈。分享/关注在此定义为曝光后窗口内的全空间事件，独立预测；若业务上必须先点击，也可建立相应漏斗，但需重新定义任务图。

用一个六分类 softmax 预测这些行为是错误的：点击、关注、分享可以同时发生。各二元任务使用独立 sigmoid，只有专家门控在专家轴做 softmax。

### 什么时候换 PLE

若正负反馈任务长期冲突或共享专家明显负迁移，可设每任务两个专属专家、两个共享专家。任务门控只访问本任务专属与共享专家；中间层的共享门控可访问所有任务专家与共享专家。最后一层只输出各任务表示。

多层 PLE 中每个专家接收其所属上一层表示，不是每层都重新读取原始输入。专家数量随任务数增长，需与增加同等参数的 MMoE 比较。

## 5. 漏斗损失的数值稳定实现

点击和条件消费 logits 为 `a,b`。令 `pQ=sigmoid(a)*sigmoid(b)`，全空间监督 `yQ`。可在 FP32 下计算：

\[
\log p_Q=\log\sigma(a)+\log\sigma(b).
\]

正例损失为 `-log_pQ`；负例损失为 `-log(1-exp(log_pQ))`，使用稳定 `log1mexp` 而非直接相减。边界处需处理浮点饱和。计算概率后粗暴 clamp 虽易用，但会改变极端区域梯度。

当 `yQ=1` 时，两个 logits 的梯度分别为 `pC-1`、`pConditional-1`，同时鼓励点击和消费；当 `yQ=0` 时：

\[
\frac{\partial L_Q}{\partial b}
=\frac{p_Cp_{Q|C}(1-p_{Q|C})}{1-p_Cp_{Q|C}}.
\]

因此低 CTR 区域对条件消费头的约束可能较弱；不能只看乘积预测准确就认定条件头已可靠。

总损失：

\[
L=L_C+\lambda_Q L_Q+\lambda_T L_{T|C}
+\lambda_S L_{share}+\lambda_F L_{follow}+\lambda_N L_{negative}.
\]

每任务先按有效 mask 的样本权重之和归一化，再加权求和。消费窗口未成熟时应 mask 掉，不是填零。时长仅在有效点击样本上监督，且需剔除加载失败等不具备消费机会的样本。

## 6. 时长与融合：避免口径重复

若时长头预测点击后分桶概率 `[B,K]`，桶代表值为 `m_k`，则 `muC=sum(pk*mk)`，曝光期望消费为 `muE=pC*muC`。尾桶需要代表值校准或单独建模，不能默认无限桶中点。

决策示例：

\[
V=w_Qg_Q(p_Q)+w_Tg_T(\mu_E)+w_Fg_F(p_F)-w_Ng_N(p_N).
\]

如果业务需要的是期望时长效用 `E[g(T)]`，应从条件分布计算 `pC*sum(pk*g(mk))`；这一般不等于 `g(pC*muC)`。选择哪一个取决于业务定义。

消费概率和时长存在信息重叠，联合使用可以表达业务偏好，但不能把双重奖励误称为互相独立的价值。线上融合权重与训练 loss 权重分开配置、版本管理。

## 7. 线上张量与计算复用

在线一个请求的 `N` 个候选可以按候选轴批处理：静态用户特征与历史编码共享，候选 query 和 DIN 权重不共享。可以分块计算 `[N,L,256]` 激活单元，避免候选与历史广播产生过大临时张量。

静态内容向量可缓存；历史序列需要按新事件刷新。缺失历史回退到空历史路径，特征服务超时使用约定缺省值并记录降级，不可悄悄混用不同版本 Embedding。

## 8. 必做实现检查与消融

- 修改 padding token 不应改变有效输出；空历史不得出现 NaN。
- `pQ≤pC` 必须成立；标签中出现 `yQ=1,yC=0` 说明口径或归因有问题。
- 改变请求后的历史不应影响本请求训练特征。
- 每个任务 head 与 gate 在有效标签下应有梯度；无有效标签的任务不贡献 loss。
- 依次比较 DNN、加 DCN、加 DIN、加 MMoE、加漏斗；额外报告推理成本与校准。
- 列表位置、封面和内容质量分开切片，检查点击收益是否被秒退抵消。
